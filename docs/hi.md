# hi: replacing pi at the terminal

**Design target, not a release checklist.** For what now runs and what still blocks cutover, see [implementation status](hi-build.md); for shipped commands see [protocol v1](protocol.md). Build `hi` in `clients/tui`, on the same authenticated daemon as Phoenix. The product test is “can I use this in place of pi for my actual coding sessions?”, not “can Ratatui display a chat?” Keep `h` working during the transition. No second agent loop, local session log, Node requirement or rewrite of the daemon.

## Reference and starting point

Baseline: `~/Projects/JavaScript/pi`, [d15b2cf43](https://github.com/Overbryd/pi/tree/d15b2cf43367f757832e8257ee5ebac76fce5d69) (coding-agent/tui 1.3.0, with a local-fork fix after the release). Compare the **interactive coding agent** to `hi`, not pi-durable's specification to the H engine. Recheck these three sources when moving the pin:

- [Interactive mode](https://github.com/Overbryd/pi/blob/d15b2cf43367f757832e8257ee5ebac76fce5d69/packages/coding-agent/src/modes/interactive/interactive-mode.ts): actual dispatch, busy queue, mode switching, extension UI. The [usage guide](https://github.com/Overbryd/pi/blob/d15b2cf43367f757832e8257ee5ebac76fce5d69/packages/coding-agent/docs/usage.md) describes the user journey.
- [Action/default binding table](https://github.com/Overbryd/pi/blob/d15b2cf43367f757832e8257ee5ebac76fce5d69/packages/coding-agent/docs/keybindings.md) and [slash command table](https://github.com/Overbryd/pi/blob/d15b2cf43367f757832e8257ee5ebac76fce5d69/packages/coding-agent/docs/slash-commands.md). Use actions as fixtures, not literal terminal bytes as an API.
- [pi-tui](https://github.com/Overbryd/pi/tree/d15b2cf43367f757832e8257ee5ebac76fce5d69/packages/tui/src) separates main/alt screens, editor, kill ring, undo stack, keyboard decoder and width calculations. Its [tests](https://github.com/Overbryd/pi/tree/d15b2cf43367f757832e8257ee5ebac76fce5d69/packages/tui/test) are a better quality bar than a screenshot: see `editor-history-keybindings`, `regression-overlay-cjk-boundary`, `wheel-scroll`, `tui-shrink` and `alt-screen-large-transcript-bench`.

H baseline: [cli.rs](../clients/tui/src/cli.rs) already selects/creates sessions, accepts `-s/-r/-c/-p`, implements branch/model/steer/abort commands, and can print a final reply without a TTY. [client.rs](../clients/tui/src/client.rs) handles UDS, literal loopback HTTP, no redirects, SSE and unary requests. Keep the [wire types](../clients/tui/src/protocol.rs), [committed vs ephemeral reducer](../clients/tui/src/transcript.rs), and [terminal sanitization](../clients/tui/src/render.rs). Today stdin is a `read_line` thread; interactive commands can block the loop; output interleaves with typing; interactive SSE errors are reported, not generally reconnected. A generation number ignores obsolete listeners but doesn't cancel a blocked read. There is no terminal editor, bounded viewport, or selectable harness in the Rust create request.

## The durable differences are part of the interface

| In pi's interactive workflow | What `hi` must do instead |
|---|---|
| Quit the application; interrupt the current turn | `/quit`, EOF, lost SSH, Ctrl-Z and closing a picker **never** abort. Esc dismisses the top interaction first; only an explicit run interrupt sends `abort`. Label its scope: active generation in this conversation, including tool work, not one selected task. Another attached user sees the outcome. |
| One local editor and queues | Draft, history navigation, selection, expanded tools and scroll position belong to this display. Accepted input belongs to the daemon. Enter = `submit(when_busy: steer, when_idle: start)`; Alt-Enter = `follow_up/start`. Let the writer decide busy vs idle atomically. Render pending → receipt → committed inbox/entry; receipt is not completion. Don't bring a queued prompt back as editable text unless the daemon atomically withdrew it. Abort is not pi's local “restore all queued messages”. |
| Navigate a JSONL tree or fork a session to edit an earlier prompt | `/tree` previews/picks visible entries and conversations locally. Show parent and cut point. Continuing at a cut creates a conversation; editing a prompt forks **before** the old input and submits the replacement, not after it. Use `fork_and_submit` where a visible predecessor exists; offer a new session for a root prompt rather than invent an entry zero. Inherited agent config is as of the cut; inbox, live work and usage are not inherited. Neither fork nor navigation rewinds files. |
| Token stream on the same process as the renderer | SSE snapshot replaces entries + `live/inbox/agent/usage`. Commit with matching `prev_seq` advances committed view; ignore stale commits. Seq is session-wide, not necessarily consecutive. `base_seq`-matched ephemerals overlay only; discard overlay on next commit/snapshot. Reconnect with last **committed** cursor; on gap request snapshot, not an optimistic patch. Never replay a model/tool call from the TUI. |
| Change settings / resume the current workspace | Scope by `(env_id, cwd, session, conversation)`, not terminal cwd alone. Session/branch/model switches must not leak drafts or accept late HTTP/SSE into the new view. Model/thinking/tool choices are shared `configure` commands (`expected_seq`, refresh on conflict); theme, editor keys and model cycle order are local. Show quarantine, workspace busy and interrupted unsafe results as such, not “retrying”. |
| App owns files, extensions, credentials, context window | Daemon owns execution environment, policy, provider credentials, projection and persisted effects. A terminal file and an environment file may not be the same file. Label source before attachment. The owner token authenticates the daemon connection, not third-party packages. H has no general approval/wait primitive. |

See [protocol v1](protocol.md) for implemented semantics. Give a create retry the same client-chosen `session_id` and check returned workspace/profile; `request_id` alone isn't idempotent creation. Retry an ambiguous command only with its original envelope. Show “outcome unknown” until reconciled; don't clear an unacknowledged draft or silently submit it again on startup.

## Parity ledger

**A** = achievable on the existing API (not necessarily in `h`); **B** = needs a specific daemon/profile capability; **C** = optional integration or intentional incompatibility, not a silent omission. Where mixed, ship A first. Use the gates in the [roadmap](roadmap.md); do not call a preview a replacement while required B items are open.

| Workflow from the pinned pi | hi implementation / boundary | Acceptance example |
|---|---|---|

Show effective profile, instructions, model, usage/cost if reported (unknown ≠ zero). B: catalog rename/delete with conflict/active-work policy. Optional daemon launcher later, never silently start a second owner. | Resume correct session in two envs with the same path. `hi -p` is clean stdout, no terminal negotiation. |
| Multiline editor, history, key rebinding, `/hotkeys`, external editor | A: editor contract below, focus-aware help generated from actual bindings; same actions in fullscreen and regular mode. | Edit yesterday's prompt without altering history; receive output while editing. |

## Rust terminal and editor decision

**Recommendation:** spike [Ratatui](https://docs.rs/ratatui/) + [Crossterm](https://docs.rs/crossterm/) for fullscreen first. Ratatui supplies layout, cell buffers/diffs, widgets and a test backend; Crossterm supplies raw events, resize, bracketed paste, mouse and keyboard enhancement flags on capable terminals. Neither supplies a pi editor or owns our session lifecycle. Compare its inline viewport to a small explicit main-screen/live-tail renderer for regular mode. Don't build a general retained widget toolkit. Unix (macOS/Linux, including tmux/SSH) first: `client.rs` unconditionally uses Unix sockets; cross-platform crates alone do not make `hi` a Windows port.

| Editor option | Useful capability | Decision for streaming chat |
|---|---|---|
| [rustyline](https://docs.rs/rustyline/) / [reedline](https://docs.rs/reedline/) | Mature prompt/history/Emacs or vi editing; completion; reedline multiline prompts and menus. Good when **the line reader** owns the terminal. | Don't run a blocking editor and a separate fullscreen renderer on the same TTY. External printing is not shared layout, IME placement or overlay focus. Candidates only for a standalone REPL. |
| [tui-textarea](https://docs.rs/tui-textarea/) or equivalent embeddable model | Feed input and draw a widget in our frame; has selection/undo/multiline editing. | Spike with pinned compatible Ratatui versions. Test wrapped vertical motion, grapheme deletion, history draft restoration, paste markers and own key dispatcher. Adopt if these fit without forking or double-handling keys. |
| Small pure `EditorState` + [unicode-segmentation](https://docs.rs/unicode-segmentation/) / [unicode-width](https://docs.rs/unicode-width/) | One cursor model for completions, atomic paste markers and cell layout. No second reader. | Fallback if widget spike fails. Own a bounded UTF-8 buffer and undo groups, not a full text editor/rope until measurement warrants it. Grapheme boundaries for edits, byte offsets for slicing, terminal columns for rendering; never interchange them. |

**Editor acceptance contract.** Enter submit; Shift-Enter or Ctrl-J newline; arrows/Ctrl-B,F, Home/End or Ctrl-A,E, Alt-B,F by word, character jump, visual-line up/down with sticky column. At history boundaries up/down browse prior prompts and return to the unsent draft; incremental history search, deduplication, bounded private history with persistence opt-out. Delete/backspace by grapheme, Ctrl-W/Alt-D word kills, Ctrl-U/K line kills, Ctrl-Y/Alt-Y kill ring/yank-pop, grouped undo/redo. Normalize CRLF; bracketed paste is one edit, never key dispatch (even pasted `/quit` or newlines); collapse large pastes into removable markers, expand exactly on explicit send. Preserve leading/trailing whitespace. Secure temp file for `$VISUAL`/`$EDITOR`, restore TTY before launch, re-enter and redraw afterwards, clean up on error. No shell interpolation of draft text.

Dispatch `terminal event → named action → focused overlay/completion → editor/application`. Document precedence (Esc closes search before interrupt; Ctrl-D deletes unless buffer empty; Ctrl-C clears before exit). Enhanced-key terminals distinguish Shift-Enter; legacy TTYs cannot distinguish all chords: provide discoverable alternative bindings, including a slash action when Ctrl-J is indistinguishable from Enter. Keep hardware cursor at focused edit cell for IME. Test accents, ZWJ emoji, flags, CJK, tabs, soft wraps and 1-column resizes. Inline pictures: Kitty placements where supported, iTerm2 regular-mode display if safe; alt-screen placeholder if placements can't be erased/cropped. OSC clipboard and link opening require explicit user gestures. Never pass provider/tool ANSI/OSC through; only renderer-generated control sequences reach the terminal.

**Why Rust here, not why Rust everywhere.** Enums/newtypes and exhaustive matches distinguish durable cursors, dispatch generations, pending vs committed states; serde decodes untrusted bytes at the wire boundary (TS types alone are erased). Ownership and a single terminal guard make resource cleanup on ordinary error/unwind systematic. Bounded queues and explicit cancellation make redraw cost and task lifetimes inspectable; no JS GC pause in that path. A locked binary removes Node/npm resolution from the *client's* startup. It still needs the daemon. These aren't correctness or speed proofs: Node has runtime validators, `finally`, streams, a mature extension ecosystem and faster hot iteration. Rust adds Unicode/cell work, builds per OS/arch, crate/MSRV churn and a poor stable in-process plugin ABI. `Drop` can't fix SIGKILL, `panic=abort`, external effects or ambiguous network writes. Use protocol tests, panic/signal cleanup, recovery instructions (`reset`/`stty sane`), measured latency and daemon checkpoints, not a “failsafe language” claim.

## Client composition (proposed; modules first)

```
TTY events / resize ─┐                     ┌─ immutable view → one terminal writer
network frames ──────┼→ AppEvent → update ─┤
receipts / timers ───┘                     └─ effects → cancellable I/O → AppEvent
```

1. Extract an internal `lib` in `clients/tui`: `config/client/protocol/transcript` stay UI-free. `h` keeps line/print compatibility; new `hi` binary selects interactive or plain output. A fake backend feeds the same events. Publish a Rust client crate only when there is an independent consumer; the stable interop contract is the wire, not Rust traits over a dynamic library.
2. `AppState` contains target + attach generation, transcript reducer, pending envelopes, editor/drafts, overlays, viewport anchor `(entry_id, row_offset)` and preferences. Reducer returns effects (`Subscribe`, `Page`, `Command`, `Complete`, `Draw`); workers own sockets, not stdout or state. Cancel/unblock old reads and join workers on switch/exit. Fence every asynchronous response by target/generation, completion by edit revision. Reconnect on EOF/error with bounded backoff and visible offline status. Disable unsafe-to-repeat actions while reconciling.
3. Keep input responsive: bounded channels, process commits in order; coalesce **draws**, not arbitrary `append_text` operations. On overflow abandon the stream and resnapshot. Page immutable history; cap cached rows/bytes around anchor and live tail, refetch evicted pages. Cache rendered blocks by entry/version, width, theme and expansion. Reflow only dirty blocks; redraw on frame ticks, not per token. Keep user input ahead of background highlighting.
4. Terminal guard owns all mode changes and unwinds partial initialization. Restore mouse, keyboard protocol, paste, cursor, alt screen and raw mode on exit/error; handle suspend/resume and resize. No worker `println!`; stderr logs redirected while interactive. Non-TTY/`TERM=dumb` path never enters raw mode. Keep safe text path for unknown entry kinds, no-color and print.
5. Keep extensibility orthogonal: presentation resources in client, harness policy in trusted daemon packages, optional tool bridge outside both. See [Extensions](extensions.md) for the proposed contributor boundaries.
